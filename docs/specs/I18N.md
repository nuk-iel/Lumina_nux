# Languages

The game runs in English (`en`, the source and the fallback), Japanese (`ja`) and Simplified
Chinese (`zh`). This document is the contract for choosing the language, the UI strings, the
content text and the fonts. The visual system is in [PIXEL_UI.md](PIXEL_UI.md).

## 1. Choosing the language

`resolveLang()` in [`src/engine/i18n/I18n.js`](../../src/engine/i18n/I18n.js) picks the language
in this order:

1. `?lang=en|ja|zh` (also `ja-JP`, `zh-CN` …). Not saved.
2. The saved choice: `localStorage['luminati.lang']`.
3. `en`.

It never reads the browser's locale: harness runs, fingerprints and screenshots stay English on any
machine.

- `src/main.js` calls `setLang(resolveLang())` before anything renders. That also sets
  `<html lang>` to `en`, `ja` or `zh-Hans`, which CSS `:lang()` and the CJK line-breaking rules
  key on.
- The title screen offers the switch (EN · 日本語 · 中文, bottom right): **L** or a pad shoulder
  button (LB / RB) gives the row the focus on the current language (pressed again, it moves on),
  **← / →** choose, **Enter** or pad A switches, **Esc** or pad B goes back; a click on a language
  switches at once. A change calls `Game.setLanguage(code)` (`saveLang()`, drops `lang` from the
  URL, reloads); scripts call `__game.setLanguage(code)`. There is no hot switch.
- The language is a device preference, not save data: a campaign save is the same in every
  language.
- The level editor shows English or Simplified Chinese (Japanese falls back to English): it reads
  the same choice (`?lang=`, then the saved language) and switches with *View › Language*, which
  saves the choice for the game too and reloads. Its play-test and its links into the game pass
  `&lang=` when the editor is not English. Its strings, catalog labels and engine messages are
  described in [§6](#6-the-level-editor).
- The launcher (`index.html`, the list of campaigns and levels) stays English too: a plain page
  outside the pixel UI. The game it opens (`game.html`) reads the saved language.

## 2. UI strings

```js
import { t, tn, tlist, sep, registerStrings, getLang, isCJK } from '../i18n/I18n.js';
registerStrings('hud', { en: { controls: 'Controls', hide: 'Hide controls' }, ja: { … }, zh: { … } });
t('hud.controls')                 // the current language, then English, then the key
t('combat.risen', { place })      // {var} slots; other braces stay ({Caldera} markup)
tn('combat.foes', 3)              // en { one, other }; ja / zh plain strings; {n} is the count
tlist(['A', 'B'])                 // Intl.ListFormat
sep()                             // ' · ' (en, zh) / '・' (ja)
```

**Tables**
- One namespace per file, holding `{ en, ja, zh }` together, so each owner edits only its own
  file.
- A feature's table is `src/game/<feature>/strings.js` (combat, party, story, campaign) or, for a
  feature's UI, `src/engine/i18n/strings/<ns>.js` (`worldfx`, `story-ui`). It exports
  `{ en, ja, zh }` and imports nothing that needs a browser, because the i18n checker reads it in
  Node.
- A feature's namespace is registered by the feature when it starts, never by a module-level side
  effect in a `*_PURE` module, so a page without the feature never loads it:

| Namespace | File | Registered by |
|---|---|---|
| `hud`, `dialog`, `map`, `title`, `game` (core) | `src/engine/i18n/strings/<ns>.js` | `registerCoreStrings()` (`strings/index.js`): `src/main.js` at the top of boot (the loading screen's steps and error page are in `game`), and the UI root again (idempotent); `DialogBox` / `InteractPrompt` register `dialog` themselves on a page that made them without a root |
| `worldfx` (Guard, Perfect!) | `src/engine/i18n/strings/worldfx.js` | the `WorldLabels` constructor (combat levels) |
| `story-ui` (journal, end card, skip hint) | `src/engine/i18n/strings/story-ui.js` | the `Journal` and `EndCard` constructors (`UI.useStoryUI`) |
| `combat` | `src/game/combat/strings.js` | the `CombatSystem` constructor, before it calls `ui.enableCombat()` (the death screen's prime reads it) |
| `party` | `src/game/party/strings.js` | the `Party` constructor and `partyUIClasses()` (`registerPartyStrings()`) |
| `story` | `src/game/story/strings.js` | the `StoryRunner` constructor |
| `campaign` | `src/game/campaign/strings.js` | `registerCampaignStrings()`: `CampaignStart` (the loading line comes first) and the `CampaignRuntime` constructor |
- An entry is a string or a function `(vars) => string`. English articles and plurals that don't
  fit `{ one, other }` use functions.

**Rules for owners**
- **Keys are ids, not English.** For example, `prompt.talk`, `enemy.slime`, `ware.whetstone.name`
  and `rule.target.leader.label`.
- **Lookups keep English.** Vocabulary that code looks up by its English text stays English in
  data and state; only the display is translated:
  - `shopWare(name)`;
  - story item names;
  - villagers matched by name;
  - region names in `_bannersShown`;
  - option labels in `[once]` keys;
  - `level.name`, which seeds randomness.
- **No grammar in code.** Separators come from `sep()`, lists from `tlist()` and counts from
  `tn()`. Word order lives in whole-sentence templates: `t('combat.attuned', { place })`, never
  `name + ' attuned'`. A keycap inside a sentence is a `{key}` slot that the component renders as
  a keycap.
- **Spacing.** The gap after a keycap is CSS, never a leading space in a string.
- **Latin stays Latin.** HP, MP, SP, XP, Lv, G, key names and numbers stay in Latin script in
  every language, as JRPGs do.
- **Node-safe tables.** `src/engine/level/PartyRules.js` and `src/game/combat/defs.js` stay
  import-free and English (Node tools import them). Translate them in the game layer by id.
- **The developer UI stays English:** the debug panel, story errors, console messages.

## 3. Terms (glossary)

Proper nouns and recurring terms follow one glossary per language,
[I18N_GLOSSARY.md](I18N_GLOSSARY.md), which kept the names the UI mockup's glossary decided: Sela
セラ / 瑟拉, Warden 衛士 / 守卫, Tactics 作戦 / 战术, Presets 方針 / 预设, Rules 指示 / 规则,
Healing Draught 回復薬 / 治疗药水, Cinderwatch Pass シンダーウォッチ峠 / 烬望隘口, and so on.

The content tables (§4) hold the place and character names, as terms. UI tables hold only UI
vocabulary. Where both name the same thing (a signpost's speaker, a waystone, the world map's
legend), they must agree: `npm run i18n:check` compares every name the content shows with the UI
string of the same English and lists the ones translated differently, or translated by the UI only
(its *UI glossary* lines). Only names are compared. A line of prose keeps its own register, so the
same words inside a sentence are not checked.

## 4. Content text

What players read from level, campaign and story data, and from the hand-written conversations in
`src/game/dialogue.js`, is translated **at display**, from
[`ContentText.js`](../../src/engine/i18n/ContentText.js). There are two kinds of content text:

- **Units: prose.** A dialogue page, a sign's paragraph, a choice's question or answer, a script's
  line, an item's or quest's text, a subtitle, a banner, a prompt's own label (a built-in verb is
  a UI string, §4.8), a title. Each has a
  **text key** stored with it in the data, a GUID as Unreal's FText keys
  (`9F2A1B3C4D5E6F708192A3B4C5D6E7F8`), made when the text is made and kept through every edit
  (§4.2); code text has a code key such as `dlg.elder.welcome`. A table's unit records the English
  it was translated from. `loc(key, source)` shows the translation only while that English is
  still the text shown.
- **Terms: names.** Villagers, speakers, places, levels, campaigns, items, quests, foes and
  waystones. In this engine a name is an identity: scripts match villagers by name, saves keep it,
  and `level.name` seeds the terrain. A name is translated by that identity: `term(name)`. A
  term is one glossary entry, so a villager's name reads the same in every level and campaign that
  shows it.

**Why keys, not the English.** Keying prose by its English text (the gettext model, and this
format's version 1) is common, but it is weaker for a game's narrative content:

- The same English line can need two translations. Japanese gives each speaker their own register,
  so a warden's "Thank you." and a child's read differently.
- Fixing a typo in the English silently drops the translation back to English.
- A line has no name that QA, voice work or a translator's notes can refer to.

Stable ids per line are the practice of game localization pipelines: Unreal's text keys with
source hashes, Unity Localization's string tables, Yarn Spinner's line ids. Here, as in Unreal, the
key is a GUID held beside its text in the data (§4.2). It travels with the text: inserting a page, reordering
lines, renaming an object or moving a line never moves a translation. The format change is
additive:

- Level, campaign and story files gain an optional `textKeys` field and `#line:` tags on script
  lines (§4.2). A file without them loads and plays as before, and a generator's re-run stays
  byte-identical: it carries its keys over from its last output (§4.10).
- The editor keys every text it makes; *Level › Assign text keys* or
  `npm run i18n:keys -- --assign` keys the rest. Until then a text without a key stays English in
  every language (a `nokey` miss, §4.2).
- A user's level has no table of its own, so it plays in English. A copy of a shipped level keeps
  the shipped level's keys, and the editor's play-test passes that level's table (§4.10).
- The editor never reads `public/i18n/`.

### 4.1 Tables

Under `public/i18n/`:

| File | Holds |
|---|---|
| `index.json` | the languages and the tables each has; nothing unlisted is fetched |
| `<lang>/common.json` | the code's units: the `loc('<ns>.<name>', '…')` lines of `src/game/dialogue.js` (`dlg.*`) and of any other module. Also the terms the code shows on every level: the shipped levels' names (`SHIPPED_LEVELS`) and the names the catalog and boot write into data (`COMMON_TERMS`: Signpost, Villager, Waystone, Untitled, Untitled campaign) |
| `<lang>/levels/<name>.json` | one per shipped level, `public/levels/<name>.json`: the units of its texts and the terms it shows |
| `<lang>/campaigns/<name>.json` | a campaign: the units of `campaign.json`, of every level file (chapter variants too) and of its story files, and the terms they show |

```json
{ "format": "luminati-i18n-index", "version": 1,
  "languages": { "ja": { "tables": ["common", "levels/emberfall", "campaigns/emberfall-interiors"] },
                 "zh": { "tables": ["common", "levels/emberfall"] } } }
```

```json
{ "format": "luminati-i18n", "version": 3, "lang": "ja",
  "source": "levels/emberfall",
  "extends": [],
  "terms": { "Elder Maren": "マレン長老", "Tobin's Farm": "トビンの農場" },
  "units": {
    "FD16B8743DD5A4C70BD9A04DC5BB7FCC": { "source": "{Tobin's Farm}. Mind the chickens.", "target": "{トビンの農場}。ニワトリに注意。" },
    "638FE502B9DB304DBD5816D5B68E29CD": { "source": "Someone has added, in smaller letters: \"They are not as friendly as they look.\"", "target": "誰かが小さな字で書き足している。…" }
  } }
```

The two units are the pages of Emberfall's farm sign. Its object in `public/levels/emberfall.json`
holds their keys:

```json
{"id":"sign_farm","type":"signpost", …, "text":["{Tobin's Farm}. Mind the chickens.","Someone has added, …"],
 "textKeys":{"text":["FD16B8743DD5A4C70BD9A04DC5BB7FCC","638FE502B9DB304DBD5816D5B68E29CD"]}}
```

**Entries**
- A unit is `{ "source": English, "target": translation, "note"?: text for translators }`. Its
  `source` is the English the translation was made from, trimmed.
- **Untranslated means absent.** A table holds only translations. An empty `target`, or an empty
  term, is an error, because it would blank the text.
- Japanese and Chinese ship fully translated: `npm run i18n:check -- --strict --complete` passes
  (0 errors, 0 warnings, nothing untranslated; 975 units and 286 terms per language). A new line
  stays English until a translator adds it (§4.7).
- The tools write keys and terms sorted by `keyCompare` (code-unit order, with runs of digits
  compared as numbers: GUIDs sort the same on every machine), with a two-space indent and LF.

**`extends`**
- `extends` lists the tables looked up after this one. A campaign built on a shipped level extends
  that level's table: `emberfall-interiors` → `levels/emberfall`.
- The campaign's `levels/emberfall.json` carries the shipped level's keys: its generator copies
  them, and `npm run i18n:keys -- --assign` shares them with a keyless copy of the same file name
  (§4.10). Where its English is the same, the shipped table translates it.
- Where a copy's English differs under a shared key, the unit is the campaign table's own, and the
  source check skips the shipped one. Diverging along `extends` is legal: each table has one
  English per key (§4.2).
- `common` is never named: it is always last.

**Where an entry lives.**
- A unit lives in the table of the file that holds its text. When an extended table already has
  the same key with the same English, the unit lives only there.
- A term lives in the extended (base) table — the one looked up last before `common` — when the
  sources of both show it; otherwise in the table whose sources show it. A term that `common`
  holds is never repeated in another table.
- The same name in tables that do not extend one another (Pip in three) is a term in each. The
  checker keeps their translations equal (§4.7).

**Other versions.** Only version 3 is read; the shipped tables are version 3 (§4.9 tells how they
came to be).
- A table file of an older version, or of none, is not read: the loader skips it with one warning
  (`ja/levels/x: version 2: not read — tables are version 3`), like a file that cannot be read, and
  its texts stay English. The checker reports it as an error; the worklist tool writes no worklist
  for it and rewrites it only with `--force=table` (§4.7).
- A newer version is read with a warning: its unknown fields are ignored.

### 4.2 Keys and lookup

Every unit of content prose has a **text key** stored with it in the data. As with Unreal's FText
keys, the key is a GUID made when the text is made: by the editor, a generator or
`npm run i18n:keys`. It is kept through every edit, so inserting a page, reordering lines or
renaming an object never moves a translation.
[`ContentKeys.js`](../../src/engine/i18n/ContentKeys.js) reads, cleans and mints the keys; it is
import-free and Node-safe. [`TextKeys.js`](../../src/engine/i18n/TextKeys.js) carries them
through edits (§4.10).

**The key.** A key is 32 upper-case hex digits (`EGuidFormats::Digits`), for example
`9F2A1B3C4D5E6F708192A3B4C5D6E7F8` (`isGuid`). A key or tag of lower-case digits is read too: the
loaders and `splitLineTag` write it in upper case (`toGuid`). Two other forms exist:
- a banner's subtitle has `<GUID>.2`, derived from its line's key (`subtitleKey`);
- code text has a hand-written **code key** beside its English:
  `loc('dlg.elder.welcome', 'Ah, a traveler. …')` (`isCodeKey`; lower case, dot-separated, no
  colon).

**Where the keys live.** `textKeys` is a side field that mirrors the translatable fields beside
it. It is optional and absent when there is nothing to key, so a file without keys is unchanged.

| Holder | `textKeys` |
|---|---|
| level object | per translatable field (`TEXT_KEY_FIELDS`): a key for a one-string field (`title`, `sub`, `banner`, `label`); a list parallel to the raw list for `text` and `locked` (`null` where an entry is blank: `textPages`); per raw dialogue page a key, or `{ "key": G, "choices": [G, …] }` (`dialogueUnits`). A choice page whose question is blank has `{ "key": null, "choices": […] }`. |
| level root | `subtitle`, `title.title`, `title.subtitle`, `title.prompt`, `title.credit` (the `environment.title` overrides). Written on one line after `objects`, in its place among the top-level fields the engine does not know (the file's order is kept: [LEVEL_FORMAT.md §14](LEVEL_FORMAT.md#14-serialisation-byte-stable-writing)). |
| `campaign.json` | its own: `subtitle`, `title.*`; each chapter: `title`, `subtitle` |
| story file | an item: `{ "text": G }`; a quest: `{ "text": G, "stages": { "<stage id>": G }, "goals": [G, …] }` (stages by the loader's id, `stageIdOf`; goals by their raw index). `buildStory` puts each key on the built item, quest, stage and goal (`textKey`). |
| script | a trailing tag on each line that holds text: `- Ah, a traveller. #line:9F2A…` (an npc's `talk`, an event's `run`, a story file's `scripts`, actors' `talk` and events' `run` — an event by the loader's id, `eventIdOf` —, and `.story` files) |

```json
{"id":"elder","type":"npc","name":"Elder Maren","dialogue":["Ah, a traveler. …",{"text":"Rest?","choices":["Not yet","Yes"]}],
 "textKeys":{"dialogue":["0A1B…",{"key":"2C3D…","choices":["4E5F…","6A7B…"]}]}}
```

**Keys are bounded by their texts.** The cleaners keep a key only where its holder has a text:
- an object's key of a field it does not hold is dropped, and a key list is cut to its field's raw
  length (a choice list to its page's: `normalizeObject(o, report)`);
- the level's own key of a title line its `environment.title` does not hold (or holds as no
  string) is dropped. A blank subtitle keeps its key, and the checks list it as stray;
- `campaign.json`'s, its chapters' and the story files' keys are cleaned but not bounded.

**Script tags.** The lines with text are a `say`, a choice's question and each option, a `bark`,
`toast`, `banner`, `quest … stage` and `ending` whose text is not blank (`holdsText`,
`scriptTextSlots`).
- `parseScript` cuts the tag off before the line is read, so no text, label, speaker or `[once]`
  key holds it. It sets the node's key (`tk`; an option's `tk`; a banner's `tks` = [G, G.2]).
- A `#line:` still in a line's text after the tag is cut (a malformed tag, a second tag) is a
  parse error, never shown to a player. A line cannot hold the words `#line:` themselves.
- A **parked** line keeps its tag for when it reads again, never gets a new one and is never
  stray (`ParsedScript.parked`): a comment, a line with an error or a line its error left out, a
  line past a script limit.
- A tag on any other line (an `if`, a `set`, a blank line) is `stray` (`ParsedScript.stray`): it
  is ignored, and the checks report it.
- A `== id` header of a `.story` file is never tagged. A tagged header is no header (its line
  joins the script before), so retagging drops the tag and the checks warn about it.

**What gets a key**
- Every non-blank text of a translatable field gets a key, the catalog's default texts included
  (a placed villager's *Hello, traveler!*). A choice page's blank question gets none.
- A label that is a built-in verb (`builtinLabel`: Enter, Look …) is a UI string and gets none.
- Names are terms, never keyed: villagers', speakers', places', levels', items', foes', waystones'
  and quests' (§4.5).

**One key, one English.**
- A key names one English text among one table's sources (§4.1): a shipped level's file, or a
  campaign's `campaign.json`, level files and story files. Copies share their keys while the
  English is the same, and so share one translation: a chapter variant and its base, a campaign's
  copy of a shipped level, a level saved under another name.
- When a copy's English changes, that copy gets a new key and the others keep the shared one with
  its translation (**copy on write**). The generators do this themselves (`assignTextKeys`'
  `base` and `shared`); the editor does it on every edit, against the campaign's other files and
  the file a *Save As* left (§4.10); `npm run i18n:keys -- --fix` splits a copy edited by hand.
  One key with two Englishes among one table's sources is an error of the checks (§4.7, §4.10).
- A campaign's copy of a shipped level is in another table. Its English may diverge from the
  shipped level's under a shared key; its own table then holds the unit (§4.1). That is no
  conflict.
- Within one file a key is used once (`textKeyIssues`: `repeated`, an error).

**Readers.** Untrusted data, so only own keys and well-formed upper-case GUIDs are read; otherwise
the result is `''`:
- `textKeyOf(holder, field)`;
- `pageKeyOf(holder, field, i)`;
- `dialogueKeyOf(holder, i)`;
- `choiceKeyOf(holder, i, j)`;
- `questKeyOf(quest, 'text'|'stage'|'goal', at)` for a story file's raw quest; a built story's
  item, quest, stage and goal carry `textKey`;
- a script node's `tk` / `tks`.

**Cleaning.** `normalizeObject`, `normalizeLevel`, `normalizeCampaign` and `buildStory` drop
malformed keys and unknown fields (`cleanTextKeys`; for a level and its objects also the keys past
their texts), and write a key of lower-case digits in upper case. `normalizeLevel` warns about
both, per object and for the level's own keys; the campaign and story loaders warn about dropped
keys only. Well-formed data comes back byte for byte.

**No English fallbacks** ([Translation lookup rules](I18N.md)). A
text is translated by its key or not at all; a translation is never found by the English, since
the same English may be another speaker's line, and a guess would hide the gap from the checks:
- **A text with no key** (a level from before keys, an ad-hoc `__game.story.run` line, a line typed
  into a file by hand and not yet keyed) stays English in every language: `loc('', text)` returns
  the English and records a `nokey` miss. The checks list it (a `missing` key; *no key* in
  `i18n:check`), and the editor's *Assign text keys* or `npm run i18n:keys -- --assign` gives it a
  key; its unit can then be translated.
- **A key no table holds** (one minted after the tables were made: a keyless level keyed by the
  editor, a renamed story id, a copy's new key, an old save's key after a prune) shows the English
  and records a `missing` miss until a translator merges its unit. The worklist lists it, with the
  translations the same English has elsewhere as suggestions (§4.7).
- **A `stale` key** (its unit records other English) shows the English until the line is reviewed.

**Lookup**

| Function | What it returns |
|---|---|
| `loc(key, source, kind?)` | In each table of the chain, the unit with `key` whose `source` is the English shown (trimmed). Else the English, recorded as a miss: `missing` (no table holds `key`), `stale` (the key's unit records other English, so the line needs review) or `nokey` (an empty `key`: the data holds none). A non-string or `''` source comes back as it is. `kind` is read by the tools only. |
| `term(name)` | The first term of the chain for the name (trimmed), else the name (a `term` miss). A name is its own key (§4.5), so this lookup by the English is the rule for names, not a fallback. |
| `contentMisses()`, `clearContentMisses()`, `quietly(fn)` | The texts shown untranslated since the chain was installed (§4.3); `fn` run without recording. |

- Text with spaces around it keeps them around the translation.
- Translate first, then fill values: `interpolate(loc(n.tk, n.text), reader)`,
  `contentFormat(loc('dlg.shopkeeper.bought', 'Obtained: ${name}'), { name })`.
- **Misses.** With a chain installed (not English), `loc` and `term` record what they could not
  translate, as `{ key?, name?, source, why }`. Each key, name or keyless English is recorded once,
  at most 500 in all:
  - `missing`: no table holds the key;
  - `stale`: the key's unit records other English, because the English was edited and the line
    needs review;
  - `nokey`: the data holds no key for the text (one miss per English);
  - `term`: no term.

  `window.__luminati.content.misses` shows them, and the tours read them (§4.8). `quietly(fn)` runs
  lookups for text not shown now without recording:
  - the glyphs a level preloads (`Game._glyphsFor`);
  - the lines of a skipped cutscene other than the page that asks;
  - the lines a test answers without a window (`__game.story.auto`).
- Tables are `Map`s, so keys and names such as `"__proto__"` and `"constructor"` are plain text
  (KNOWN_ISSUES LVL-17).

### 4.3 Loader API

[`ContentText.js`](../../src/engine/i18n/ContentText.js) is Node-safe: it imports nothing.

```js
import { loc, term, contentFormat, loadContentTables } from '../engine/i18n/ContentText.js';
import { pageKeyOf } from '../engine/i18n/ContentKeys.js';
await loadContentTables(getLang(), { level: 'emberfall' });   // or { campaign: 'ferrymans-lantern' }
dialog.show({ speaker: term(npc.name), text: interpolate(loc(node.tk, node.text), reader) });
hud.toast(loc(pageKeyOf(sign, 'text', i), line));
```

| Export | Does |
|---|---|
| `loc(key, source, kind?)` | a unit's translation, or the English (§4.2) |
| `term(name)` | a name's translation, or the name |
| `contentFormat(template, params)` | fills `${name}` slots of a code template, after `loc` |
| `loadContentTables(lang, o)` | loads and installs a chain; resolves to `{ lang, tables, strings, warnings, chain }` |
| `installContentTables(lang, tables)` | installs parsed tables in lookup order (and forgets the misses) |
| `setContentTables(content)` | installs one anonymous table (tests, sandbox pages): `{ terms?, units? }` as in a file |
| `clearContentTables()` | back to English |
| `contentInfo()` | `{ lang, tables, strings, units, terms, missCount, missDropped }` of the active chain (`strings`: every entry; `missDropped`: misses past the 500 kept) |
| `contentMisses()`, `clearContentMisses()`, `quietly(fn)` | the misses (`{ key?, name?, source, why }`); `fn` run without recording |
| `parseContentTable(raw, { id, lang })` | a table file → `{ table, warnings }`; drops unusable entries; `table` is null for a file that is no object or not version 3 (one warning) |
| `parseContentIndex(raw)` | `index.json` → `{ languages: Map<lang, Set<id>>, warnings }` |
| `contentTableIds(o)`, `isTableId(id)` | the table ids a page asks for (`{ campaign?, source?, level?, tables? }`); the id rule |
| `CONTENT_KINDS`, `CONTENT_FORMAT`, `CONTENT_INDEX_FORMAT`, `CONTENT_VERSION` (3), `CONTENT_INDEX_VERSION` (1) | constants |

[`ContentKeys.js`](../../src/engine/i18n/ContentKeys.js):

| Export | Gives |
|---|---|
| `LINE_TAG`, `isGuid`, `toGuid`, `isTextKey`, `isCodeKey`, `subtitleKey` | the key rules: `'#line:'`; a GUID (upper case); 32 hex digits of either case as the GUID, else `''`; a key `loc` looks up (a GUID, `<GUID>.2`, a code key); a code key; a banner subtitle's key |
| `randomGuid()`, `guidOf(seed)` | a new key: random (Web Crypto, never `Math.random`), or derived from a seed (the same seed, the same key) |
| `splitLineTag(line)`, `tagLine(line, key)` | a script line's `{ text, tag }`; the line with its tag set (`''`: removed) |
| `TEXT_KEY_FIELDS`, `LEVEL_TEXT_FIELDS`, `CAMPAIGN_TEXT_FIELDS`, `CHAPTER_TEXT_FIELDS` | the fields that hold keys: per object type each field's kind (`text`, `lines`, `dialogue`, `script`); a level's, a campaign's and a chapter's own texts |
| `textKeyOf`, `pageKeyOf`, `dialogueKeyOf`, `choiceKeyOf`, `questKeyOf` | the readers (§4.2) |
| `cleanTextKeys(raw, kinds, holder?)`, `cleanTextKeysOf(type, raw, holder?)`, `cleanQuestTextKeys(raw)` | the cleaners the loaders use: `{ keys, dropped, upcased }` (§4.2) |
| `BUILTIN_LABELS`, `builtinLabel(label)` | the prompt's built-in verbs (UI strings, not units, §4.8) |
| `textPages(v)` | a `lines` field's pages `{ i, text }` |
| `dialogueUnits(v)` | a villager's dialogue pages `{ i, text, choices: { j, text }[] \| null }` |

[`TextKeys.js`](../../src/engine/i18n/TextKeys.js) carries the keys through edits for the editor,
the generators and the tools (§4.10). The game never imports it, so it stays out of the game's
chunks.

`loadContentTables(lang, { level?, campaign?, source?, tables?, fetch?, read?, base?, install? })`:

- **English resolves at once and fetches nothing.**
- Otherwise it reads `index.json` once per page. Then it reads only the tables that file lists for
  `lang`: the ones asked for, the tables they extend, and `common`.
- `campaign: 'x'` asks for `campaigns/x`, and nothing else: the campaign's table holds every level
  file of it (`?level=` there is the start level), and a shipped level it builds on comes in through
  `extends`.
- Without a campaign: `source`, the loaded level's (`levels/emberfall.json` → `levels/emberfall`),
  else `level`, the `?level=` value slugified as `LevelStorage.slugify` does (`Emberfall` →
  `levels/emberfall`). Prefer `source`: a name with no Latin letters has a hashed file name only
  `source` knows. A `local:…` level asks for none, so it gets `common` only.
- `tables: ['levels/<name>']` adds a table, for example a play-test's `&i18n=levels/<name>`.
- What names no table id is left out with a warning.
- It never throws. A missing or broken file stays English, with a warning.
- In the browser it fetches `<BASE_URL>i18n/…`. Node passes `read(path)` (`nodeReader()` in
  `tools/lib/i18n.mjs`), or `fetch` and `base`.
- `install: false` returns the chain without installing it.

### 4.4 Markup

Translate first, fill values second: `interpolate(loc(key, text), reader)`,
`contentFormat(loc(key, t), params)`.

- Gold `{word}` is translated inside the braces (`{Emberfall}` → `{エンバーフォール}`). The number
  of spans may change (a warning).
- Key hints stay verbatim: `{T}`, `{~}`, and code slots in gold such as `{${attack}}`.
- `${…}` story values and code slots: the same set as the English (an error otherwise). A value may
  appear more or fewer times than in the English. `\${x}` (an odd run of backslashes) is no value:
  `interpolate` shows it as written.
- Braces must balance (an error).
- Sign line breaks (`\n`) and arrow glyphs are kept (a warning otherwise).

### 4.5 Translate at display: identities stay English

Never write a translation into the loaded level, campaign or story objects. An overlay applied at
load would also feed the build-ahead, the hash checks and the `__luminati` hooks. These values look
like text but are looked up, saved or hashed:

| Value | Why it stays English |
|---|---|
| `level.name` | seeds the terrain noise and combat's RNG; `_shippedSlug` |
| villager `name` | scripts match villagers by name (Game, Party, combat hooks, `StoryRunner._speaker`); the party record saves it |
| region `name` | the key of `_bannersShown`; `state().region` |
| villager `item` | `combat.buy` / `priceOf` match `SHOP_WARES`; `story.giveNamed` matches story item names, and an item no story file declares keeps the name it was given by (`StoryState.itemNames`), so the journal and the toasts show `term(that name)` |
| a choice option's label | part of the `[once]` key `opt:<where>:<line>:<label>` |
| saved quest texts | `StoryState` keeps the title and stage texts (see below) |
| exit and event `label` | tests assert `'Enter'`: translate only in the prompt |

These identities are exactly the names translated as terms (§4.2): a name is its own key.

- **Saved quest texts.** A script's `quest <id> start <title>` saves the title. That title is a
  term, shown as `term(title)`. `stage <s> <text>` saves the text with its `${…}` values filled in
  (`StoryRunner._quest` → `StoryState`), and beside it, additively, the text's key and its English
  before the values (`q.keys[stage]`, `q.src[stage]`). The journal shows:
  - a text without values (the saved text is its English): `loc(key, src)`, translated;
  - a text with values: the saved text as it is, English, with no miss — write such texts without
    values (the checker warns about one that has them);
  - a text saved without a key (an ad-hoc `__game.story.run` line's): the saved text, English, a
    `nokey` miss.

  Only a GUID is kept as a stage's key. A saved key that is not one is dropped on load together
  with its English, so that text is shown as saved, in English (`nokey`).
  A story file's declared quest texts carry the keys of the quest's `textKeys` (the built stage's
  `textKey`) and are filled in at display, so they have no such limit.
- Choices are positional: a level's choice page keeps its length, each choice translated alone
  (`choiceKeyOf`).
- `StoryRunner._trace` records the source text.
- **Never extracted:** ids, flags, conditions, entrance and marker names, a house's `name` (the
  editor's label only), `to`, `actor`, item, quest and script ids, a level's `description` and
  `author`.

### 4.6 What is extracted

[`ContentStrings.js`](../../src/engine/i18n/ContentStrings.js) is Node-safe; only the tools import
it. Each entry is either:
- a unit `{ key, text, kind, where, field, note }`, where `text` is the English, trimmed; or
- a term `{ term: true, text, kind, where, field, note }`.

`note` holds the speaker, the line before and after, and the object type. `where` is a readable
place (`levels/emberfall.json › elder (npc) › dialogue[2]`). The extractor pages and numbers text
with the same functions the runtime uses (`textPages`, `dialogueUnits`, `scriptTextSlots`).

A unit's `key` is the key the data holds for it, read as the runtime reads it: `textKeyOf`,
`pageKeyOf`, `dialogueKeyOf` and `choiceKeyOf` for level objects and a level's own texts; the
`textKeys` of `campaign.json` and its chapters; the built `textKey` of a story item, quest, stage
and goal; a script slot's tag (`slotKey`: an option's `tk`, a banner's `tks[0]` and, for its
subtitle, `tks[1]`, otherwise the node's `tk`). So every key it lists is a key the game asks for.
A text whose data holds no key is listed with `key: ''`: no unit can be made for it (the game shows
it in English in every language), and the checker says so (§4.7).

| Data | Units | Terms |
|---|---|---|
| level | `subtitle`, `environment.title.*` (single levels only: a campaign shows the campaign's title screen) | `name` |
| house, well, signpost | each page of `text` | the sign's `speaker` |
| villager (`npc`) | `title`; each `dialogue` page and each of its choices; each line of `talk` that holds text | `name`; `item` where a conversation offers it (the shop action, or a `shop` command in its talk script or its actor's) |
| region | `sub`, `banner` | `name` |
| exit (a campaign's level files only) | `label` (`mode: use` only; not a built-in verb), each page of `locked` (with `requires` only) | — |
| event | `label` (used with Space only; not a built-in verb), each line of `run` that holds text | — |
| enemy, waystone | — | `name` |
| campaign | `subtitle`, `title.*`, each chapter's `title` and `subtitle` | `name` |
| story files | each item's and quest's `text`, each stage's text, each goal, every script's slots | item, quest and actor names; the speakers of `say` lines (as resolved: a villager's or actor's name; a bark shows no name) |
| every script (talk, run, story) | its slots (above) | the item a `give` / `take` hands over (the story's name for it, else `titleCase(id)`; gold is none) and the quest a `quest` command names (the story's title, else the title a `quest … start` gives, else `titleCase(id)`), as `StoryRunner` shows them (`storyNames`) |
| code | every `loc('<code key>', '<English>', kind?)` call under `src/game/` and `src/engine/` (`scanLocCalls`) | the shipped level names and `COMMON_TERMS` |

A shop villager with a blank `item` offers the UI's default (`t('game.default.item')`), but a
story keeps what it gives under the identity 'Crisp Apple', and its journal shows that name. So
'Crisp Apple' is a term of a level's own table where a story runs there and such a shop offers it,
and nowhere else; no shipped level has one.

**Left out, because the game never shows them:**
- exits on a single level (the game reads exits only in a campaign);
- a walked exit's prompt;
- the locked text of an exit with no `requires`;
- the prompt of an event not used with Space;
- an item no conversation offers;
- dialogue that a talk script, the actor's talk or a hand-written conversation replaces
  (`SHADOWING_SCRIPTS`), except where the talk runs `builtin shopkeeper` (or, on a peaceful level,
  `builtin drillmaster`), which plays the villager's pages;
- on a combat level, the `drillmaster`'s pages, the `shopkeeper`'s `item` and its pages with
  choices (the combat shop shows its plain pages only).

**Code**
- A code key and its English are literals: `loc('dlg.shop.not-enough-gold', 'Not enough gold')`.
- A template uses `${name}` slots in a plain string, filled by `contentFormat`.
- A call whose key and English are both data (`loc(pageKeyOf(sign, 'text', i), line)`,
  `loc(node.tk, node.text)`) shows data by the key the data holds. It is counted, not extracted:
  its text comes from the data's tables.
- These are errors:
  - a code key with an English that is not a literal (a template with `${…}`, a literal joined
    with `+`), or an empty English;
  - a literal key that is not a code key, or a key built in code;
  - a literal English beside a key that is not a literal (a default for blank data is a UI
    string, §4.8);
  - one code key with two different Englishes (one error per key, across files);
  - a call joined with `+` to more text;
  - unbalanced braces, an unknown literal kind, a call that never closes.
- A code default that stands in for blank data is a UI string, not content (§4.8).

### 4.7 Checker, worklist and exchange

`npm run i18n:check -- [--lang=ja] [--table=…] [--strict] [--complete] [--json] [--verbose] [--quiet]`
([`tools/check-i18n.mjs`](../../tools/check-i18n.mjs), read-only) checks every table the index
lists against the units and terms its **readers** show. A table's readers are itself and every
listed table whose lookup chain holds it (a campaign reads the shipped level it extends); `common`
is read by every table and by the code.

**A unit's state.** A unit's key is the key the data holds beside its text, kept through every
edit, so a unit is looked for at its own key only: nothing moves. Each unit is:

- **used:** a reader shows its key with its recorded English;
- **changed:** else a reader shows its key with other English that lives in this table: the same
  key, another source. The line was edited, and the game shows the English until it is reviewed. A
  unit that another reader still shows with its old English (a line edited in a shipped level
  whose campaign copy is not) stays used for that reader, and the edit is reported for the other.
  When the unit's old English now sits at the key beside it in the same field, the warning adds a
  hint: the keys may be out of step with their texts after a hand edit of `textKeys`
  (`npm run i18n:keys -- --check`);
- **orphan:** anything else, with the reason (`why`): no source holds its key (its text was
  deleted, or its file left the table), its key now shows English that another table holds (that
  table translates it there), or it is no text key at all. When a source of the table, or of a
  table that reads it, had errors (a level file that does not parse, a missing story file,
  `src/game/levels.js` failing to import for `common`), its orphans are marked **source
  unreadable**: they may well be in use.

The report:

- **Volume:** the English to translate per table: units and terms, characters, words, and
  estimated Japanese and Chinese characters.
- **Untranslated:** units (key, English, where) and terms with no translation on a reader's chain,
  reported against the table they live in (§4.1). The game shows them in English: a unit is found
  at its own key only, never by its English (§4.2).
- **Changed, orphans** (warnings): each changed unit with its old and new English (and the
  out-of-step hint), each orphan with its reason (`--prune` drops it, unless its source is
  unreadable).
- **No key** (warnings): the unit texts the data holds no key for, one line per table, with how
  many, the first places and what to run (`npm run i18n:keys -- --assign`; the editor's *Assign
  text keys*; a generated file: its generator). They stay English in every language until keyed.
  They are not counted as untranslated, because no worklist can name them.
- **Errors:**
  - markup errors (§4.4);
  - an empty or non-string `target`, `source` or term, and anything else the loader drops — a
    table file that is not version 3 among them (not read at all, §4.1);
  - one key with two different Englishes among one table's own sources (a copy of a line edited
    apart, a tag pasted onto another line), with both Englishes and places and the hint
    `npm run i18n:keys -- --fix`. A campaign's copy of a shipped level may differ from it along
    `extends`: those are two tables' sources. For a code key: two calls with two Englishes;
  - a listed table file that is missing or names another language or source;
  - an `extends` the index does not list;
  - `loc()` errors in the code (§4.6).
- **Warnings:**
  - gold spans, line breaks, missing key hints or arrows;
  - a target identical to the English (info for terms);
  - a gold `{Term}` span whose translation is not the term's;
  - a term translated differently in two tables;
  - a table file the index does not list;
  - a script's quest text with `${…}` values (§4.5).
- **UI glossary** (§3): a name the UI and the content both show, translated differently, or
  translated in the UI only (`uiGlossary` in [`tools/lib/i18n.mjs`](../../tools/lib/i18n.mjs)).
- A file that is not JSON (the index or a table) is an error line, never a crash.
- `--json` prints the whole report: per table its untranslated entries, `changed`, `orphans`,
  `sourceErrors`, `errors` and `warnings`; `noKey` (per table, every text with no key);
  `summary: { errors, warnings, untranslated, ms }`.
- Untranslated entries are neither errors nor warnings. Exit code 1 on errors (with `--strict`, on
  warnings too; with `--complete`, on anything untranslated too); 2 on a usage error (an unknown
  option, a missing value, a `--table` the index does not list, `--sync`).

Translators work table by table with [`tools/i18n-worklist.mjs`](../../tools/i18n-worklist.mjs):

1. `node tools/i18n-worklist.mjs --lang=ja --table=levels/emberfall` writes
   `.check/i18n-worklist/ja/levels/emberfall.json`, version 3:
   `{ format, version, lang, table, count, chars, units, terms }` (`format`:
   `luminati-i18n-worklist`), in the order the game's files hold the text.
   - `units[]`: each untranslated or changed unit as `{ key, source, target: '', kind, where,
     speaker?, before?, after?, type?, previous?, suggestions? }`: its key (the GUID), its English,
     where it is used (readable places: the file, the object, the field; at most ten listed), the
     speaker, the lines before and after, and the object type.
   - A changed unit has `previous: { source, target }`, the old English and its translation.
   - `suggestions: [{ target, from }]`: the same English translated elsewhere in the language's
     tables (translation memory).
   - `terms[]`: each untranslated term as `{ name, target: '', kind, where, suggestions? }`.

   `--format=po` writes a gettext PO file instead, for CAT tools and translation platforms:
   - The header has `Language`, `X-Luminati-Table` and `X-Luminati-Worklist-Version` (3), and the
     `PO-Revision-Date`, `Last-Translator` and `Language-Team` that `msgfmt --check` asks for.
   - `msgctxt` holds the key (the GUID; `term` for a term), `msgid` the English and `msgstr` the
     translation.
   - `#.` lines hold the notes (`kind:`, `speaker:`, `before:`, `after:`, `type:`, `suggestion:`,
     `where:`). `#:` says where the text is used, as `<file>:<key>` or `<file>:<line>`, with no
     white space, because gettext tools split references on it.
   - A changed unit is `#, fuzzy` with `#| msgid` set to the old English and an empty `msgstr`. The
     old translation is a `#. previous translation:` note: it does not translate the new English.

   No worklist is written for a table the loader does not read (not JSON, not version 3) or that
   is filed under another language or table than its `lang` and `source` say (exit 1; the other
   tables are written). The tool also says how many unit texts have no key in the data: no
   worklist can list them (`npm run i18n:keys -- --assign` first).
2. Fill in `target` (or `msgstr`), keeping the markup. Remove a changed entry's `fuzzy` flag once
   it is reviewed (a JSON entry may carry `"fuzzy": true` too, and is skipped the same way).
3. `node tools/i18n-worklist.mjs --merge=.check/i18n-worklist/ja` merges JSON or PO files (a file or
   a folder) into the tables.
   - It writes the extractor's English as each unit's `source`, never the file's, and the targets
     with LF line ends. A byte-order mark and a PO `Language` written `ja_JP` are accepted.
   - A unit that another reader still shows with its old English (a line edited in a shipped level
     whose campaign copy is not) is kept for that reader, in the table it lives in for it, before
     the new translation replaces it.
   - It skips blank targets, fuzzy entries and entries whose English is no longer the English at
     their key. It always skips keys that are no text key, keys and names that live in another
     table (a worklist for `common` merges only the code's units and the common terms) or that no
     reader shows, and a fuzzy entry whose translation is still the old one.
   - It refuses a worklist that is not version 3 (a PO file: its `X-Luminati-Worklist-Version`), a
     markup error, a table the index does not list, a table the loader does not read (not JSON,
     not version 3), is misfiled or is of a newer version, and a table whose own or readers'
     sources had errors.
4. Run `npm run i18n:check -- --lang=ja` (for a shipped language, `--strict --complete`).

`node tools/i18n-worklist.mjs --prune` drops orphan units and terms. It takes `--lang`, `--table`
and `--dry-run` (write nothing), and refuses the tables a merge refuses. `--sync`, which moved
translations to new keys after a line was inserted, is gone: nothing moves now, and the tool exits
2 with that reason. An inserted page is a new unit to translate while its neighbours stay
translated, and a renamed object keeps its keys and translations.

`--force` overrides every refusal; `--force=<kind>[,…]` overrides only those named:
- `fuzzy`: merge fuzzy entries (never one whose translation is still the old one);
- `english`: merge an entry onto the English now at its key;
- `markup`: merge a translation with a markup error (each is printed);
- `table`: rewrite a table the loader does not read (not JSON, not version 3), misfiled or newer;
- `sources`: merge or prune a table whose own or readers' sources had errors.

The worklist tool exits 1 when something was refused and 2 on a usage error. A new shipped level or
campaign gets its tables from `node tools/i18n-worklist.mjs --init`. A new language gets them from
`--init --lang=<code>`. `npm run i18n:test` (`tools/test-i18n.mjs`) is the self-test.

### 4.8 Call sites

Every display site translates the data it hands to the UI; UI components stay string-in.

**Keys come from the data shown.** Every site reads the key from the object or file it shows, with
the readers of §4.2. A text therefore keeps its translation wherever it is shown: in a room set
aside and attached again, in a world built ahead, on a Space exit or event another module added.
- A level's interactables keep their pages' keys (`InteractText.keys`, read by `World` with
  `pageKeyOf`; a door's pages are its house's). An exit's or event's prompt reads its object
  (`it.object`).
- A villager's title key is read when the villager is built (`npcDef.titleKey`:
  `textKeyOf(obj, 'title')`). Its dialogue pages and choices are read from its level object
  (`dialogueKeyOf`, `choiceKeyOf`).
- A party member shows what the data it stands for holds: on its villager's level, the villager's
  level object (`storyObj`: its title, talk script and pages); on any other level its story
  actor's talk script, whose lines carry their own tags. Away from its villager's level it holds no
  title and no pages (a stand-in `{ id, actor }`).
- A script's lines carry their tags: `parseScript` sets `tk` / `tks`, and `StoryRunner` caches
  each parse by its source key and the tagged text.
- A story's items, quests, stages and goals carry the `textKey` the story file holds
  (`buildStory`).
- A campaign started on a chapter variant (`&level=<variantId>`, a play-test's `&as=<variantId>`)
  plays the variant's text as its base level, and `fileId` stays the base id (saves, travel,
  `state().campaign.file`). The start passes the variant's id to
  `CampaignLevels.override(id, text, textFile)` as `textFile`, so the game's `source` is the
  variant's file (`CampaignLevels.textPath(fileId)`; every travel takes it from
  `CampaignRuntime.sourceOf(fileId)`). The game shows that file's keys, shared with the base where
  the English is the same.

| Data | Shown with |
|---|---|
| level and region names, villager names and speakers, item, quest, actor, enemy, waystone and campaign names | `term(name)`; a villager's plate is `villagerName(npc)`, which shows `t('game.default.villager')` for a villager the level left without a name |
| a sign's, house's or well's text | `loc(text.keys[k], line)`: the interactable keeps each page's key (`InteractText.keys`, from `pageKeyOf(obj, 'text', i)`; a door's pages are its house's). An interactable without `keys` shows its lines as they are |
| a villager's dialogue pages and choices (dialogue.js) | `loc(dialogueKeyOf(obj, i), text)`, `loc(choiceKeyOf(obj, i, j), choice)` (`showPages(units, obj)`, `dialogueUnits`) |
| a villager's `item` | `term(item)`, looked up only for the shop action; a blank one shows `t('game.default.item')` |
| a villager's `title` | `speakerTitle(npc)`: `loc(npc.def.titleKey, title)`; a talk script's line the same way (`StoryRunner._titleOf`) |
| a region's `sub` and `banner` | `loc(textKeyOf(region, 'sub' / 'banner'), text)` |
| an exit's or event's prompt; an exit's locked pages | `promptLabel(it)`: a built-in verb (below), else `loc(textKeyOf(it.object, 'label'), label)`; `loc(pageKeyOf(exit, 'locked', i), text)` |
| the level's subtitle and title screen | `loc(textKeyOf(level, 'subtitle' / 'title.<k>'), text)` |
| a script's texts (talk, run, story scripts) | `loc(node.tk, text)`, `loc(option.tk, label)`, `loc(node.tks[0/1], …)` |
| campaign subtitle, title screen, chapter banners | `loc(textKeyOf(campaign, 'subtitle' / 'title.<k>'), text)`, `loc(textKeyOf(chapter, 'title' / 'subtitle'), text)` |
| story item, quest, stage and goal texts | `loc(x.textKey, text)` on the built story |
| dialogue.js's own lines | `loc('dlg.<conversation>.<name>', 'English')` |

**Code defaults for blank data are UI strings** (`t()`), never content:

| Default | Key |
|---|---|
| Signpost | `game.default.signpost` |
| Villager | `game.default.villager` |
| Waystone | `game.default.waystone` |
| the chest and waystone examine lines | `game.default.chest`, `game.default.waystoneText` |
| Nothing of note. | `game.default.nothing` |
| A Luminati 2.5D Level | `game.default.subtitle` |
| Press any key | `game.default.prompt` |
| Luminati 2.5D Pixel-Art Engine · three.js | `game.default.credit` |
| Crisp Apple | `game.default.item` |
| Enter / Look (a blank exit or event label) | `game.prompt.enter` / `game.prompt.look` |
| The way is closed. | `campaign.exit.closed` |
| The End | `story.ending.default` |

- Defaults the catalog writes into data are data: the names `Signpost`, `Villager` and `Waystone`.
  So are the names `Untitled` and `Untitled campaign` that boot writes into `level.name` /
  `campaign.name`. These names are common terms.
- 'Crisp Apple' is the identity a shop with a blank `item` gives (the inventory, `story.giveNamed`).
  Where the game shows it, it shows the UI string; only a story's journal names it, so it is a term
  only where a story keeps it (§4.6).
- **Built-in verbs are UI strings.** An exit's or event's label that is one of the prompt's
  built-in verbs (`BUILTIN_LABELS`: Talk, Examine, Knock, Read, Look, Enter, Rest, Open — the
  catalog writes `Enter` into exits) is shown with `t('game.prompt.<id>')` and is no unit, so
  translators get it once. `promptLabel` asks `builtinLabel(label)` first, and `loc` only for any
  other label.

**Tours.** Two harness suites show the content through the game's own display, in Japanese or
Chinese, and fail on any miss (`window.__luminati.content.misses`), a keyless text shown (`nokey`)
among them. They assert no English text (KNOWN_ISSUES I18N-10), so they mean the same in every
language; in English they record no miss and must run without a page error.

- `sandbox/i18n.tour.json` (`sandbox/i18n_tour.js`, `window.IT`) visits one level:
  `npm run check -- --page=game.html --query="level=<name>&autostart=1" --out=<out> --fps=0 --lang=ja --script=sandbox/i18n.tour.json`.

    left the level).
  - A villager whose talk may end the story or leave the level (an `ending` or a `travel` in its

    left up.
  - A report-only scan lists the runs of Latin letters left in the visible UI for a human to read;
    it never fails the run.
  - The six shipped levels pass in ja and zh with 0 misses. Starfall Vale and Gildhaven take about
    5 and 7 minutes.
- `sandbox/i18n.campaign.json` (`sandbox/i18n_campaign.js`, `window.CT`) covers the campaigns, the
  story and the party:
  `npm run check -- --page=game.html --query= --out=<out> --wait=0 --fps=0 --lang=ja --script=sandbox/i18n.campaign.json`
  (the script navigates itself). Real dialog windows are paged with real key presses, never the

  - *The Ferryman's Lantern*, from its title screen to its ending: every level file toured with

    checked on the end card and again on the title with its Continue line.
  - *Emberfall — Open Doors*: the town and its 10 rooms, each entered through its exit and toured.
  - Cinderwatch Pass: Sela declines, then joins; the tactics panel; her talks as a member; the two

  - Besides the misses it checks only where the story stands (flags, levels, the files played, the

### 4.9 Current format and compatibility

Only version-3 translation tables and worklists are supported. Prose uses a GUID stored beside
its source text, and names use glossary terms. Each translated unit records the English source
it was reviewed against. Inserting or moving a line keeps its translation; editing its English
keeps its key and marks the translation for review (§4.2).

Earlier table formats and positional keys are not read. An unsupported table is skipped like an
unreadable file (§4.1); a worklist must use version 3 (§4.7). There is no supported migration tool
for earlier formats in this repository.

For current content, use `npm run i18n:keys -- --check` to validate keys,
`npm run i18n:check` to identify missing or changed translations, and the worklist workflow in
§4.7 to review and merge translations. Edit generators rather than generated level files.

### 4.10 Keys through edits: the editor, the generators, the tools

[`TextKeys.js`](../../src/engine/i18n/TextKeys.js) is how anything that changes text keeps its
keys, as Unreal keeps an FText's key: an edited text keeps its key (its translation then waits for
review), a moved text keeps its key, a new text gets a new one, and a removed text takes its key
with it. It is Node-safe and imports nothing from `src/game`. The editor, the generators and the
tools import it; the game does not.

**Every pass works in two phases.** First each text keeps the key it may keep (its own, or the old
text's) while that key is free. Then the texts left get new keys. A new key is never one already
taken, nor one the previous file held.

**`used`** is the set of keys the **rest** of the level holds: every other object's, and the
level's own texts' when an object is edited. It is never the edited object's own keys. A key in
`used` counts as taken elsewhere, so passing the object's own keys gives each of its texts a new
key and loses every translation. `carryObjectText`, `carryRootText` and `retagScript` require it
(a `TypeError` without it).

**The functions**
- `alignTexts(old, new, { blind?, anchor? })` pairs each new text with the old text it continues;
  each old text is continued at most once:
  1. equal texts in order: the unchanged ends, then the longest common subsequence of the middle.
     A long middle (more than 2¹⁸ cells) is first cut at its anchors, texts that appear once on
     each side (`anchor`; never a blank line or a line without text);
  2. moves: a new text still unpaired takes an equal old text that no new text continues, so a
     reordered line keeps its key;
  3. edits within a run (the texts left between two equal pairs): each new text with an old one at
     least `SIMILAR` (0.5) alike, the most alike first. `similarity` is the share of words in
     common, in order, for texts of three words or more, and of characters for shorter ones;
  4. edits across runs: what is left, the same way, so a line moved and edited in one edit keeps
     its key;
  5. with `blind` (the default, for the editor): what is still left in a run, in order, when as
     many old as new texts are left there. The generators pass `blind: false`: two unlike texts
     never pair just for standing at the same place.

  The similarity work has a budget (30 million cells): past it, the texts left get new keys
  instead of stalling. The same input gives the same result.
- `carryObjectText(old, obj, mint, used, { shared? })` sets `obj.textKeys` and the tags of `obj`'s
  scripts after an edit:
  - each text keeps the key of the old text it continues while that key is free;
  - new texts get `mint(seed, { field, text })`;
  - removed and blank texts lose theirs;
  - a key is used once in the level.

  With `old` null, the object's own keys are the old ones: `carryObjectText(obj, obj, mint, used)`
  fills in missing keys and replaces keys that are taken elsewhere. A script line's own tag always
  counts first.
- `carryRootText(prev, next, mint, used, { shared? })` does the same for a level's own texts
  (`subtitle`, `environment.title.*`) or a campaign file's.
- `retagScript(old, new, mint, used)` tags a script's lines that hold text. A parked line keeps its
  own or the old line's tag and never gets a new one; any other line loses its tag.
  `stripScriptTags(v)` is the script without its tags.
- `carryCampaignText(prev, raw, mint, used?)`: `campaign.json`'s own texts and each chapter's
  title and subtitle, chapters matched by the loader's id (`chapter-<n>` for one without), a
  repeated id by its occurrence.
- `carryStoryFile(prev, raw, mint, used?)`: a story file's items, quests (the text, stages by
  `stageIdOf`, goals aligned by text), `scripts`, actors' `talk` and events' `run` (events by
  `eventIdOf`, a repeated id by its occurrence). After the match by id, a second round over the
  keys still free: a text whose English is the only one of its kind (an item's, quest's, stage's or
  goal's text, a script line) in the previous file takes that text's key when its holder is gone or
  no longer holds that English. A renamed item, quest, stage, script, actor or event keeps its
  translations.
- `retagStoryText(prevText, text, mint, used?)`: a `.story` file, script by script (`== id`; a
  repeated id by its occurrence). A line of a new or renamed script takes the tag of the one
  previous line with its text. Headers are never tagged, and the file's line ending is kept.
- `assignTextKeys(level, { previous, base, extended, shared, mint, used })`: the generators' pass
  (below).
- `textKeyIssues(level)` lists a level's `missing` keys, `stray` keys and tags (an object's key or
  tag on no text; a key of the level's own texts whose field has no text) and `repeated` keys (an
  error). `fileKeyIssues(kind, file)` does the same for a campaign file, a story file and a
  `.story` file, where a tag on a `== id` header is stray. A tag on a parked line is no problem.
- What a file holds: `levelKeys(level)` (every key, with where it is); `levelTexts`,
  `campaignTexts`, `storyFileTexts` and `storyTextTexts` (every text that takes a key, as a
  `KeyedText`: `{ key, text, where, field, set(key) }`); `scriptTextLines(lines)` (the lines that
  hold text); `similarity(a, b)`.
- Minting: `randomGuid` in the editor; `seededMint(prefix)` in the generators and the tools, a key
  derived from the prefix, the text's seed and a counter (`guidOf`: the same input gives the same
  keys). The prefix is a repository-relative POSIX path (`public/levels/gildhaven.json`) or a file
  stem. `seededMint` throws on an OS path (a `\`, a drive, a leading `/`), whose keys would differ
  between machines.

**Copy on write** (`shared`): a map of `key → the English other files of the table hold it with`.
A text keeps such a key only while its English is one of those. An edited text gets a new key,
and the other files keep the shared key and its translation.

**The editor.** Keys are never edited by hand, but they are shown:
- **Read-only keys.** Under each translatable field the inspector shows each text's key on a
  monospace line with a Copy button (a text without one says so); a field of several texts —
  pages, a dialogue, a script — keeps its key lines behind a "Text keys (n)" toggle. Level settings
  shows the subtitle's key. The key buttons are not in the Tab order, and nothing there writes to
  the level.
- **Edit › Find by text key…** (`edit.findTextKey`) takes a GUID in any case, with or without
  braces and hyphens, a `#line:` tag or a banner subtitle's `<GUID>.2`. It selects the object
  (showing it again if hidden), selects the page or line in its field and marks its key line; for
  the level's own texts it names the field. It searches the open level. A key that another file of
  the campaign holds, or the file a *Save As* left, is named in the "not found" message.
- **Scripts.** A script field and its pop-out show and compare the script without tags. On Apply
  the lines are retagged against the object's old lines.
- **EditorState** keeps the keys inside the edit's own transaction, so undo and redo restore them:
  - `addObject`: every text of the new object gets a key, the catalog defaults included;
  - `insertObjects` (paste, duplicate): a key that is already in the level is replaced and a
    keyless text gets one, so a duplicate gets fresh keys and a cut-and-paste keeps its own;
  - `updateObject`: only the fields the edit changed carry their keys (`carryObjectText`). The
    other fields keep theirs exactly, and a keyless text the edit left as it was stays keyless
    (and English in every language until *Assign text keys*). No translatable field changed:
    nothing is done;
  - `setLevelProps`: the level's own texts, by the same rules; a `textKeys` patch is merged into
    the level's, never replaces them.
- **What an edit keeps.**
  - A field cleared and typed again gets its old keys back. The editor remembers them per object
    and field (and for the level's own texts) until another level is loaded; an id rename takes the
    memory along.
  - An unchanged text keeps a key the document had when it was loaded rather than one minted since:
    of a line duplicated above itself and then edited, the original keeps its key.
  - A key the edit brought in that another text of the level holds is not kept: a script line
    pasted with its `#line:` tag keeps its old key or gets a new one. A patch that writes
    `textKeys` keeps them, cleaned, unless they hold such a key (or a key another file holds with
    other English); the object is then filled as *Assign text keys* fills it.
- **Copy on write.** An edit that changes the English of a text whose key another file holds with
  other English gives the text a new key (`shared`). The other files are the campaign's other
  level, story and campaign files (`EditorState#otherTexts`, from the campaign's story context),
  and the file a *Save As* left, read back from where it lives, the level API or the browser slot
  (`addCopiedTexts`; saving back over that file forgets it). Each split is remembered: a text typed
  back to the other file's English takes the shared key back while the level holds it nowhere
  else.
  - Not covered: edits made before a *Save As*, a redo of such an edit, edits before the campaign
    context has loaded, a file opened from disk, and the shipped level a campaign extends (another
    table, where divergence is legal). `npm run i18n:keys -- --fix` is the safety net for those.
- **Opening and saving** never add or change a key: a file opened and saved unchanged stays byte
  for byte. *Save As* keeps the keys, so a copy shares its translations until its English changes.
- **The play-test** of a level outside a campaign passes `&i18n=<origin>` (`EditorState#origin`):
  the table of the project file the document was opened from (`levels/<name>`; a campaign's level
  plays inside its campaign, with its table). A document opened from a browser slot, a file on disk
  or a new level takes the table of the first project file it is saved to, and a *Save As* keeps
  it. The origin is not saved: reopened in a later session, a *Save As* copy plays with its own
  table, which does not exist, so it stays English.
- **Level › Assign text keys** (`level.assignTextKeys`), one undo step:
  - every text without a key gets one, keys and tags on no text are dropped, and the later text of
    a repeated key gets a new one;
  - a key on texts of two Englishes stays with the copy whose English another file holds under it
    (else with the first);
  - a keyless text of a campaign's level first shares keys as `npm run i18n:keys -- --assign`
    does: a chapter variant takes its base level's, and a campaign's copy of a shipped level (the
    same file name) the shipped level's, for the same object, field and English;
  - new keys are never ones the level held.
- **Check for problems** lists the text keys: missing and stray keys summed into one line each, and
  each repeated key on its own line (at most 20). For a key on two texts of the same English the
  line names *Assign text keys*; for two Englishes it names `npm run i18n:keys -- --fix <file>`,
  since the tables decide which copy keeps the key. Places are named as Find names them
  (`npc_2 › dialogue, page 1`, `pip › talk, line 4`). These lines never block a play-test.
- **Tests** can make the editor's keys deterministic with `__editor.seedTextKeys(prefix)`; it
  throws for an OS path or an empty prefix.

**The generators.** Each calls `keyLevel(level, { root, file, base?, shared? })`
(`tools/lib/levelgen.mjs`) on what it built, after normalizing and before writing. `keyLevel` runs
`assignTextKeys(level, { previous, base, shared, mint: seededMint(file) })`, and the generator
fails on any text-key issue (`keyIssueLines`: the bar of `level:check --strict`).
- `previous` is the generator's last output: the file at its default path, as the working copy has
  it (never `--out`, so a dry run gives the same keys).
- `assignTextKeys` keys every text in five steps, each over the whole level before the next
  (objects the previous output has come before new ones):
  1. the same object (type and id) and field in `previous`, the same English (equal texts aligned
     in order, a moved text too);
  2. the same English, when only one text of that type and field had it in `previous` and its
     holder is gone or no longer has it (an object renamed, a text moved to another object);
  3. a chapter variant's text whose base level (`base`, already keyed) has the same English at the
     same object and field: the first of the base's keys there still free. Likewise `extended`, a
     campaign's copy of a shipped level (another table, so its texts may diverge);
  4. an edit: the same object and field in `previous`, a changed English at least `SIMILAR` alike,
     unless `shared` holds that key with other English (copy on write);
  5. a new key from `mint`, never one that `previous`, `base`, `extended` or `shared` holds.

  A key the base holds with other English is never kept: the variant's changed text gets its own
  key and is listed in `split`. `assignTextKeys` returns `{ carried, shared, minted, split }`.
- New texts are minted from their seed (the file, the object, the field, the place and the text),
  so a re-run gives the same file (`--check`).
- *The Ferryman's Lantern* passes each base level `shared`: the keys its chapter variants' previous
  files hold (`copyKeys`). A base edit then gets a new key, and the variant keeps its translation.
  `splitSharedKeys` after it is a safety net that no longer changes anything.
- The campaign generators key `campaign.json` (`carryCampaignText`), the story file
  (`carryStoryFile`) and the `.story` text (`retagStoryText`) the same way, each against its
  previous file.
- `make-emberfall-interiors` copies the shipped Emberfall's objects with their keys and keys its
  rooms with `keyLevel`. A town text without a key fails it, with the hint
  `npm run i18n:keys -- --assign public/levels/emberfall.json`.

**`npm run i18n:keys`** (`tools/i18n-keys.mjs`):
`[<file|campaign> …] [--shipped] [--check | --assign | --fix] [--force] [--quiet] [--root=<dir>]`.
- A file or campaign is a level file, a campaign folder (or its `campaign.json`) or a name
  (`public/levels/<name>.json`, else `public/campaigns/<name>`). `--shipped` is the tracked shipped
  tree; `--check` with nothing named reads it too.
- `--check` (the default) lists each file's `missing`, `stray` and `repeated` keys, and every key
  one table's sources hold with two Englishes (per table, §4.2). It writes nothing.
- `--assign` gives every keyless text a key, drops stray keys, and gives the later text of a key
  repeated with the same English a new one. A chapter variant's keyless text shares its base's key
  where the English is the same, and a campaign's copy of a shipped level (the same file name)
  shares the shipped level's. It never replaces a text's own valid key: while any key has two
  Englishes in a table's sources (a copy edited apart, a key on two different texts, keys swapped
  by hand), it writes none of that table's files and says to run `--fix` first.
- `--fix` resolves each key with two Englishes in a table's sources.
  - First it realigns. When a copy's English is what the tables record under another key held by a
    text of the same field of the same file (and that text does not read so itself), the two keys
    are swapped back, so keys a hand edit shifted keep both translations. A keyless text of that
    field that reads what the tables record under the copy's key takes it.
  - Then it splits what is left. The copies in the highest-ranked files keep the key: a generated
    file, then a tracked one, then a user's. Among those, the copies with the English the tables
    translate keep it, else the base level's (not a chapter variant's), else those of the first
    file in POSIX path order.
  - Every other copy gets a new key (copies with the same new English share one), and every
    language's table unit of that English moves to the new key with it, so `--fix` writes tables
    too.
- New keys are seeded by the file's repository-relative POSIX path (a file outside the tree: its
  name), so every machine makes the same keys.
- It writes only the files named, or the tracked shipped tree with `--shipped`, and the tables of a
  key it re-keys. Each file keeps its line ending. It never touches a user's untracked file unless
  that file is named. Generated files change only through their generators: `--assign` and `--fix`
  refuse them and name the generator to run. `--force` writes a file whose unchanged round trip is
  not byte-identical (a hand-edited file, then written in the format's own layout).
- Exit code 0 when nothing is left to report (or everything was written), 1 when a problem remains
  or a write was refused, 2 on a usage error or a file that cannot be read.

**The checks**
- `npm run level:check` adds an info line (`text keys: N of M texts keyed`) and reports
  `textKeyIssues`: missing keys summed into one line (those texts stay English in every language),
  stray keys one per line, as warnings (errors with `--strict`, which is the generators' bar). A
  repeated key is always an error.
- `--campaign` also reports the key problems of `campaign.json` and of each story file (missing
  keys one by one up to three, else summed into one line), a key the campaign's files hold with two
  Englishes (an error), and an info line counting the keyed texts and the keys shared by copies in
  two files.
- `npm run i18n:check` reports the unit texts with no key (a warning per table), a key with two
  Englishes among a table's own sources (an error), a table that is not version 3 (an error),
  changed units with the out-of-step hint, and orphans (§4.7).
- `npm run keys:test` (`tools/test-text-keys.mjs`) is the self-test of the keys, the carry
  functions, the extractor's keys and the key tool.

## 5. Fonts

The rule: **try Google Fonts first; if that fails, load the copies built into `dist/`**. There is
no subsetting or other runtime optimisation.

| Set | Faces | Loaded |
|---|---|---|
| Latin | Jersey 10, Jersey 15, Tiny5 | always |
| ja | DotGothic16, Noto Sans JP 500/700 | Japanese only |
| zh | Noto Sans SC 500/700/900 | Chinese only |

`src/engine/ui/FontLoader.js` handles each set in turn:

1. **Google.** Fetch the Google `css2` stylesheet (timeout 2.5 s), insert it, and probe the set with
   `document.fonts.load` (timeout 2.5 s).
2. **Fallback.** On any failure, `import()` the set's `@fontsource` CSS (probe timeout 8 s). Vite
   emits those files into `dist/assets` (woff2 only); they are fetched only then.
   - In mode `auto` the failure is **remembered for a day** (`localStorage['luminati.fonts.fail']` =
     `{ t, why }`): the next page loads skip Google and go straight to `dist/`. A Google that hangs
     (a firewall dropping the packets) otherwise costs the timeouts on every boot. After a day
     Google is tried again; a success forgets the failure. Measured on the build with Google
     black-holed: the first load 3.8–4.0 s (`loadMs`; it was 4.4 s with the stylesheet hanging and
     7.5 s with the font files hanging), the next 1.44–1.47 s, as with Google reachable.
3. **Aliases** (Japanese and Chinese). The size-adjusted Jersey aliases (G's "G Num"/"G Big",
   named by role here) are `FontFace`s built from whichever Jersey file loaded, at the face and
   whole-pixel size the scale picks (§5.1). They are rebuilt when `--px` changes; with each, its
   pixel glyphs' alias ("Lu G Body" …).
4. **Pixel glyphs** (every language). The arrows ← ↑ → ↓ ↔ ↕ ↖ ↗ ↘ ↙ and ♪, which no Jersey face
   has, are TrueType fonts generated at run time on the grids of Jersey 15, Jersey 10 and Tiny5
   ([`GlyphFont.js`](../../src/engine/ui/GlyphFont.js)): "Lu Glyph 15", "Lu Glyph 10",
   "Lu Glyph 5", added as `FontFace`s from bytes — nothing is downloaded from Google or `dist/`.
   Every role's stack names the one on its face's grid (PIXEL_UI.md §2.1).
5. **`ensure(text)`.** Loads the slices a new string needs (CJK fonts come in unicode-range
   slices) before it is measured: one `document.fonts.load` per role font with the characters
   past ASCII not asked for in that font before (a character asked for again waits for its first
   load), never `document.fonts.check`. **`fontsIn(text, font)`** answers whether they are in, per
   character, from the status of the face the browser draws it with (`check()` cannot: it answers
   true for an unloaded slice of a family installed on the system — Noto Sans SC on many Chinese
   Windows machines).
   - The game starts the glyphs of what a level shows first with the world build
     (`Game._glyphsFor`) and awaits them before the HUD's first layout; once play starts,
     `src/main.js` (`prefetchGlyphs`) loads the glyphs of every translated text the page can show
     — the content tables and the core UI tables — in the background (idle time), so a dialogue
     opened later lays out at once.
   - A component that lays out text in a font that is not in yet lays it out again when it arrives
     (the UI root, the title, the journal, the barks, the end card, the party UI).

**Overrides.** `?fonts=auto|google|local` (or `localStorage['luminati.fonts']`) forces a path;
`google-fail` and `gstatic-fail` make Google's stylesheet or its font files unreachable (tests of
the fallback: they point at `https://127.0.0.1:9/`, an unsafe port the browser refuses at once, so
the fallback starts after ≈ 0.7 s instead of the 2.5 s timeout). The harness passes `--fonts`
(default `local`, so screenshots do not depend on the network or on Google's newer CJK builds) and
`--lang`. `window.__luminati.fonts` reports
`{ lang, mode, px, sources: { latin, ja?, zh? }, ms, googleError, remembered, localError, aliases, glyphs }`;
`__game.state().fonts` a short form `{ mode, px, sources, ms }`.

**The page's own fonts.** Only the UI's three sets load (Jersey 10, Jersey 15 and Tiny5, plus
the language's CJK set): Cinzel, Crimson Pro and Pixelify Sans left the game in phase 3 (with
`--fonts=google` nothing else is requested; the game's CSS went from about 170 kB to 27 kB). The
editor still imports Cinzel 600 from its `@fontsource` package. The loading screen in
`game.html` moves each text to the UI fonts only once its characters' faces are loaded; before
that, Japanese and Chinese texts use the system's CJK faces (Yu Gothic or Meiryo, Microsoft YaHei:
never the names "Noto Sans JP / SC", which the page itself declares, so a text would wait
invisible).

### 5.1 The loader's API

```js
import { startFonts, currentFonts, resolveFontMode, FONT_SETS } from '../ui/FontLoader.js';
const fonts = startFonts({ lang, px });   // src/main.js, at the top of boot (a UI made without one starts it)
await fonts.ready;                        // never rejects: the report once every set and the aliases are in
await fonts.ensure(strings);              // a string, or anything whose JSON holds the strings
await fonts.setScale(px);                 // UI.js on a scale change: the CJK aliases rebuilt (UI.js emits 'scale' after)
fonts.report;                             // = window.__luminati.fonts
```

| Export | What it is |
|---|---|

**The aliases.** One FontFace per role, `"Lu J Head"`, `"Lu J Name"`, `"Lu J Body"`, `"Lu J Line"`,
`"Lu J Small"`, `"Lu J Val"` (`layout/type.js ALIAS`): ASCII, `·`, `×` and the Latin-1 and Œ œ

synthesised bold), from the Latin file of Jersey 15 or Jersey 10 found among the page's
`@font-face` rules; after each, its pixel glyphs' alias (`GLYPH_ALIAS`, "Lu G Head" …: the glyph
face of the same grid with the same `size-adjust`).

whole-pixel Jersey cap — 15·k device px for Jersey 15, 10·k for Jersey 10 — nearest to G's
proportion of cap to the role's CJK ink at that scale (G's cap at px 2 ÷ G's ink at px 2 × the
role's ink now); a tie goes to G's face. `size-adjust` is that Jersey size over the CJK role's own
size:

**The build.** `vite.config.js` (`fontsourceWoff2Only`) cuts the woff fallbacks out of every
@fontsource stylesheet (the build emits woff2 only) and sets the new faces to `font-display:
block` like Google's. The fonts' CSS is reached only through the loader's `import()`s: nothing of
it is in what game.html links or preloads. Measured on `vite preview` with the cache off: the
Latin set 140–300 ms from dist/ (3 CSS of 0.15 kB, 3 woff2) and 160 ms from Google; Japanese or
Chinese 135–145 ms from dist/ and 180–185 ms from Google; a forced Google failure falls back in
135–145 ms. These times depend on the network and the machine (a phase-3 run measured 2.5–2.7 s
for a forced failure while the fail address still waited for the timeout; it now fails at once).
dist/ holds 682 woff2 files (15 MB; Noto Sans JP and SC are most of it).

## 6. The level editor

The editor (`editor.html`, `src/editor/`) shows English or Simplified Chinese. Japanese, the third
game language, shows the editor's English.

- **Choice.** `src/editor/langBoot.js`, the first import of `src/editor/main.js`, calls
  `initEditorLang()` (`src/editor/i18n.js`): `setLang(resolveLang())`, the `editor` string table
  registered, the catalog localized. Every other editor module evaluates after it, so a
  module-level `tr()` reads the right language. *View › Language* runs `EditorApp#setLanguage`:
  it asks about unsaved changes, `saveLang()`, drops `?lang=` and reloads. `editor.html` words its
  boot splash from the same choice before any module loads.
- **UI strings.** Namespace `editor`, one module per area in `src/editor/strings/` (`common`,
  `app`, `dialogs`, `panels`, `tools`, `story`; keys carry the area prefix, `strings/index.js`
  merges and checks them), read with `tr(key, vars)` / `trn(key, n, vars)`. English entries
  reproduce the editor's English exactly: the browser suites click and match it. Lists use
  `andList` ("a, b and c" / "a、b和c"), never `tlist` (its serial comma would change the English).
- **Catalog.** The object catalog and the tile types hold English display text beside data.
  `localizeCatalog()` (`src/editor/catalogI18n.js`) turns their display properties — type label
  and help, field label and help, `{ value, label }` option labels, enemy names, the player-start
  label, tile names — into getters that read `src/editor/strings/catalog.js` (keyed by the English
  text) in Chinese; bare option values and palette categories read `optionLabel()` /
  `categoryLabel()`. Stored values (`type`, `category`, field keys, option values, tile chars)
  never change, and nothing is installed in English, in Node or in the game.
- **Engine messages.** Load warnings and errors (`LevelFormat`, `LevelStorage`), travel issues,
  story-script and story-check messages and condition errors read the tables `levelmsg`
  (`src/engine/level/strings.js`) and `storymsg` (`storyStrings.js`), with English byte-identical to
  the old text (Node tools and tests stay English: nothing calls `setLang` there). `StoryCondition.js`
  imports nothing and takes its Chinese wording through `setConditionWording()`. A Chinese game
  shows these messages in Chinese too.
- **Identity, not wording.** Logic never reads translated text: dialog buttons resolve by `key`
  (`ui/Dialog.js`); a status message passes `{ error: true }` (the English-word guess stays only for
  untranslated callers); play-test problems use `validateLevelIssues()` codes; a newer file uses
  the parse result's `newer`; a missing project level the load error's `code: 'level.notFound'`.
  Defaults written into data (`Untitled`, `Villager`, `Waystone` …) stay English.
- **Typography.** `editor.css` `:lang(zh-Hans)` rules add a CJK face to every stack (Noto Sans SC,
  loaded in slices by `main.js` when the editor shows Chinese, over Microsoft YaHei / PingFang SC),
  draw Chinese quotes, dashes and the ellipsis full-width (`le-cjk-punct`), and drop capitals and
  letter-spacing. The 2D map's canvas text adds the CJK faces in Chinese (`Map2DView` `uiFont`).
- **Terms.** Industry terms stay as they are (3D, 2D, UI, ID, JSON, NPC, GUID, HP, MP, Lv, key
  names); game names follow [the glossary](I18N_GLOSSARY.md) and the game's string tables.
- **Checks.** `npm run editor:i18n:test` (`tools/test-editor-i18n.mjs`): every English key has a
  Chinese entry and the reverse, the same `{var}` slots, full-width punctuation after Chinese text,
  every literal `tr()` key defined, every catalog text and bare option value translated and no
  stale catalog entry. The editor browser suites run in English (the harness default) and must
  pass unchanged; `--lang=zh` runs them, or a tour, in Chinese for screenshots.
